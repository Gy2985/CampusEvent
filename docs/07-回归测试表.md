## 5. 真实服务冒烟（17 项，摘要）

启动 `app.py` 后，用 HTTP 依次完成：登录页 → 管理员登录 → 三个后台页 → 学生登录 → 活动列表 →
直接报名 → 详情统计（1/0/1）→ 重复报名被拦且记录仍 1 条 → 站内消息 → 审核型报名（0/1/50）→
管理员审批 → 学生侧变为已通过（1/0/49）→ 越权访问被重定向 → 未知路径不白屏。

结果：**17 项全部 PASS**（脚本与输出见实验报告附录说明）。

## 6. 缺陷记录与修复

| # | 现象 | 定位 | 修复动作 | 复测 |
| --- | --- | --- | --- | --- |
| D-01 | 测试导入 `RegistrationEventType` 失败 | 事件枚举被放进了 `domain.entities` | 枚举归属改到 `events.events`，测试改导入 | 36 例全绿 |
| D-02 | X14 期望 1 条却返回 2 条 | 演示数据本身含“软件工程前沿讲座” | 判断为**测试预期错误**，关键字改为“讲座专场” | 通过 |
| D-03 | 详情页“取消报名”是空表单，路由不存在 | 模板引用了未实现的路由，读模型缺 `my_registration_id` | 读模型补字段，模板改为提交 `student.cancel` | 手工验证取消后统计从 1 变 0 |
| D-04 | 重置数据库后活动 ID 变为 5、6、7、8 | `initialize()` 用 DELETE 清表，AUTOINCREMENT 不回退 | 改为 DROP + 重建表 | 冒烟脚本改为从库中读取 ID，避免硬编码 |
| D-05 | 容量可下调到低于已通过人数 | `ActivityService.update` 缺校验 | 增加“不得低于已通过人数”校验 + 测试 X8 | 通过 |
