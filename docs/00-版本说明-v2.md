# 版本说明（v2）：哪些文件是"优化前"，哪些是"优化后"

> 一句话规则：**v1（优化前）的文件名保持不动、内容不覆盖；v2（优化后）的文件名统一带 `-v2`。**
> 这样教师可以把同一份实验的"变更前 / 变更后"两套材料并排对照，也能确认我没有偷偷改昨天的报告。

## 1. 代码：用 Git 标签区分，而不是复制文件

| 版本 | Git 引用 | 内容 |
| --- | --- | --- |
| 优化前 | 标签 `baseline-v1`（8 次提交） | 实验二初始版本：两种报名方式、站内通知 |
| 优化后 | 分支 `change-v2` / 标签 `change-v2` | CR-01 年级限定 + CR-02 模拟邮件（51 项测试全过） |

查看差异：

```bash
git diff --stat baseline-v1..change-v2                 # 全部差异
git diff baseline-v1..change-v2 -- campus_event tests  # 只看代码
git diff --stat baseline-v1..change-v2 -- campus_event/services/registration_service.py  # 应为空
```

## 2. 文档：v1 保留原名，v2 加后缀并排存放

| v1（保持不动） | v2（本次新增/更新） | 关系 |
| --- | --- | --- |
| `docs/06-需求变更影响分析.md` | `docs/10-需求变更影响分析-CR01-CR02-v2.md` | v1 是没拿到 CR 时的预案；v2 是逐条拆解真实 CR |
| `docs/07-回归测试表.md` | `docs/07-回归测试表-v2.md` | v2 只追加，不改 v1 的 36 项记录 |
| `docs/05-设计模式决策报告.md` | `docs/12-设计模式决策报告-v2.md` | v2 补写新增策略/端口的取舍理由 |
| `docs/09-实验二报告.docx` | `docs/09-实验二报告-v2.docx` | v2 正文 = v1 全文 + 追加三章（变更实施/回归/指标） |

报告成稿建议：**提交 v2 报告**（内容更全），v1 报告留在仓库里作为"变更前"证据。
